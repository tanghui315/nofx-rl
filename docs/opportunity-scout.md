# 机会挖掘与提示词调参 Agent 技术方案

## 1. 背景与问题

- 现有执行 Prompt 偏“合规与风控官”，强约束叠加导致开单率低，特别是 adaptive_v7 的历史模块为硬闸门。
- 缺少“主动找机会”的模块，无法根据近期市场状态与己方绩效自适应调整阈值与偏好。
- 需求：在不牺牲核心风控（BTC 门槛、清单、SL/TP）的前提下，提高候选机会召回与优质进场频率。

## 2. 目标 / 非目标

- 目标
  - 建立“数据闭环”：记录指标轨迹与事后标签，沉淀可用样本。
  - 新增“机会挖掘/调参 Agent”（Scout/Tuner），基于日志产出可回滚的“策略覆盖（policy overrides）”。
  - 保留原有风控为硬边界，仅对“阈值/权重/试探单”做轻量可控调节。
  - 提供灰度-评估-回滚的上线机制及量化指标。
- 非目标
  - 不在此阶段引入复杂的深度学习/外部依赖；优先可解释、轻量方法。
  - 不改交易引擎/风控底线，不移除 BTC 门槛、清单、SL/TP 及冷却等硬规则。

## 3. 架构概览（职责解耦）

- 执行 Agent（现有）：
  - 严格执行风控与决策流程；读取“策略覆盖”以微调阈值/权重；不做学习。
- 机会挖掘 Agent（Scout）：
  - 任务：从近期样本中提炼“高胜率/高RR”的特征模板（机会模板），提升候选召回。
  - 输出：人类可读的机会总结报告 + 结构化模板供 Tuner 使用。
- 调参 Agent（Tuner）：
  - 任务：根据机会模板与绩效数据，生成“策略覆盖（policy_overrides.json）”与回测/重放评估报告。
  - 输出：覆盖文件（参数微调）、变更说明、灰度开关。
- 日志与评估：
  - 统一日志规范、离线评估脚本、报表（候选/开单/胜率/盈亏比/Sharpe/回撤）。

## 4. 数据闭环设计

### 4.1 记录时点
- 每次扫描 tick（含被拒绝的边缘机会）
- 开仓后：T+15m/T+60m/T+240m 打点（PnL、浮盈/回撤、是否触发 SL/TP）

### 4.2 特征（精简可解释）
- 多周期结构（15m/1h/4h）：价格相对 EMA20、EMA20 斜率、MACD 符号/斜率、RSI 区间（<30/30-40/40-60/60-70/>70）、前高/前低突破标记
- 量价情绪：成交量 Z 分数、资金费率分位数、OI 变化率（5/15/60m）
- BTC 环境：多周期一致性评分、是否在整数关口±2%、当日波动分位
- 机会对齐度：清单命中数、是否触发假突破禁开
- 风控状态：冷却状态、Sharpe 档位、连续亏损计数、账户仓位占比/持仓数

### 4.3 标签
- 二分类：入场后 X 分钟收益是否超过阈值（自适应阈值=ATR/百分比）
- 回归：期望收益/风险比、最大浮盈/回撤、是否命中 SL/TP

### 4.4 存储与结构
- 存储：`logs/trading/` 下按日 JSONL（先简洁可读，按 UTC 日滚动；也可按小时滚动以减小单文件体积）
- 命名：`YYYY-MM-DD-trade-log.jsonl`、`YYYY-MM-DD-trade-labels.jsonl`
- 条目示例（简化）：
```
{
  "ts": "2025-01-01T12:00:00Z",

  "reason": "decision_tick|open|reject",

    "m15": {"price_over_ema20": 1.01, "macd_sign": 1, "rsi_band": "50-65"},
    "h1":  {"price_over_ema20": 1.02, "macd_sign": 1, "rsi_band": "40-60"},
    "h4":  {"price_over_ema20": 0.99, "macd_sign": -1, "rsi_band": "40-60"},
    "vol_z": 1.8, "funding_pct": 0.002, "oi_chg_15m": 0.035,
    "btc_state": {"multi_tf": "neutral", "near_round": false, "day_vol_pct": 0.04},
    "checklist_hits": 4, "fake_breakout_flags": []
  },
```

## 5. 机会挖掘（Scout）

### 5.1 方法
- 轻量统计与可解释模型：
  - 特征重要性：信息增益/互信息/点二列相关（目标=短窗正收益）
  - 逻辑回归/朴素贝叶斯：输出可解释权重，避免黑箱
  - 分组对比：按 Regime（趋势/震荡/高波动）与品种拆分胜率/盈亏比
- 模板提炼：
  - 选择“强区分度”的组合特征（如：多周期共振+量能放大+负费率回归中性+OI>+3%）
  - 产出自然语言模板 + 结构化规则（供 Tuner 使用）

### 5.2 Regime 识别
- 指标：ATR 分位、布林带宽度、区间突破/假突破比、当日振幅
- 标签：趋势、震荡、高波动、事件日

### 5.3 输出
- 报告：最近 N 天机会总结（Top 模板、样本量、胜率、RR、Sharpe）
- 模板文件：`analytics/opportunity_templates.json`
```
{
  "regime": "trending",
  "template_id": "trend_vol_oi_combo_v1",
  "if": {
    "tf_agree_min": 3,
    "vol_z_min": 1.5,
    "oi_chg_15m_min": 0.03,
    "funding_band": "-0.005..0.005"
  },
  "metrics": {"support": 142, "winrate": 0.64, "rr_mean": 2.8, "sharpe": 0.9}
}
```

## 6. 调参（Tuner）与策略覆盖（Policy Overrides）

### 6.1 覆盖原则
- 不触碰硬规则（BTC 门槛、清单、防假突破、SL/TP、冷却的最小值）
- 仅调整软参数：信心阈值（微调）、清单命中下限（在关键三项齐时放宽）、冷却期微调、试探单开关与预算、历史参考权重
- 所有参数设置上下限与 TTL（过期失效）

### 6.2 覆盖文件结构 `config/policy_overrides.json`
```
{
  "meta": {"generated_at": "2025-01-01T23:30:00Z", "ttl_hours": 48, "approver": "manual"},
  "global": {
    "confidence_threshold_base": {"value": 80, "min": 78, "max": 85},
    "checklist_min_hits": {"default": 4, "allow_3_if": "key3_strong"},
    "cooldown_minutes": {"base": 9, "min": 6, "max": 12},
    "trial_entry": {"enabled": true, "confidence_band": "78..80", "risk_budget_pct": 0.5}
  },
  "regimes": {
    "trending": {"confidence_threshold_base": 79, "btc_gate_weight": "high"},
    "ranging":  {"strategy": "mean_revert_pref", "cooldown_minutes": 8}
  },
  "symbols": {
    "SOLUSDT": {"max_concentration_pct": 25},
    "ETHUSDT": {"confidence_threshold_base": 83}
  },
  "history_weights": {"winrate": 0.5, "similar_losses": -0.3, "global_sharpe": 0.5, "cap": 6}
}
```

说明：
- `btc_gate_weight` 取值枚举：`high|default|low`，仅影响信心评分的权重倾向；不改变 BTC 门槛作为硬性约束是否必须通过（硬护栏不可被覆盖）。

### 6.3 Tuner 流程（夜间/定时）
1) 读取近 N 天日志与标签 → 生成模板与绩效分解（按 regime/品种）
2) 依据样本量与显著性阈值，提出参数微调建议（带区间与上限）
3) 生成 overrides 与“变更理由 + 回测/重放报告”（`analytics/reports/*.md`）
4) 灰度开关与限额（交易频次上限、单笔风险预算上限、持仓数上限）
5) 人工审批后生效；TTL 到期自动回退默认

## 7. 工作流与调度

- 日志采集：实盘 Tick → 写 JSONL；定时 T+ 打标签
- 分析调参：每日 1 次（可增量），生成模板与覆盖
- 执行读取：执行 Agent 每次决策前读取覆盖（无则用默认）
- 监控报表：每日出“候选/开单/胜率/RR/Sharpe/回撤/拒绝原因 TopN”

## 8. 灰度与评估

- 灰度策略：
  - 覆盖启用首周：
    - 单笔风险预算下调 30%
    - 每日最大新开仓笔数上限（如 6）
    - 关键参数变更幅度上限（如 阈值±2 分）
- 评估指标：候选召回率、开单率、胜率、RR、Sharpe、MaxDD、回撤恢复时间、样本量
- A/B：moderate vs moderate+overrides；对同时间段行情回放对比
- 回滚：删除/重命名覆盖文件即可恢复默认；或 TTL 过期自动回退

## 9. 安全与风控护栏

- 任何时候保留以下硬边界：
  - BTC 多周期门槛、4/6（或 moderate 的 4/7）清单、防假突破、SL/TP、清算距离、冷却期下限
- 覆盖文件需校验 Schema 与值域；异常即忽略
- 覆盖生效需满足最小样本量（如 ≥200 样本、≥30 次触发），且报告通过人工审批

- 缺失/过期处理：若 `ttl` 过期或文件缺失，直接使用默认参数

## 12. 风险与对策

- 过拟合/数据漂移：滚动窗口、显著性门槛、最小样本量、cap 变更幅度
- 数据质量：字段校验、缺失值回退、版本化 Schema
- 相关性失效：Regime 切换检测、模板 TTL 与失效自动下线
- 人为错误：审批门槛、变更审计日志、快速回滚

## 13. 里程碑与任务（建议）

- M1 日志与标签最小集（仅记录，不影响策略）
  - 定义 JSONL Schema、写入点位、目录与轮换

  - 统计/可解释模型、Regime 识别、模板导出

## 14. 验收标准（首版）

## 16. Intraday 模式（分钟/小时版）

本节针对纯日内（分钟/小时，24/7）交易，给出刷新节奏、窗口、算法与产出规范。

### 16.1 刷新节奏
- 微刷新（与交易扫描同步）：每 3 分钟
  - 目的：检测是否命中“关键三项”（趋势共振+放量+BTC 支持）等强证据场景
  - 产物：短效“运行时覆盖头”，TTL 6–12 分钟，仅在触发关键模板时注入
- 主刷新：每 30–60 分钟
  - 目的：用最近 24–72 小时分钟数据重算机会模板与显著性
  - 产物：覆盖文件（policy_overrides.json），TTL 2–6 小时；仅做小幅微调（阈值±1、冷却±1 分钟、允许关键三项齐时 3/7 + 试探单）
- 事件触发（可选）：Regime 突变、拒绝原因分布突变、表现显著恶化 → 立即执行一次“主刷新”（TTL 30–60 分钟的临时覆盖）

### 16.2 数据窗口与标签（分钟/小时）
- 样本窗口：近 24–72 小时（分K为主），对近期样本做指数衰减权重（半衰期 6–12 小时）
- 多周期特征：5m / 15m / 1h / 4h（4h 仍属小时级，保留趋势指示力）
- 标签：与持有预期匹配的多档评估窗
  - T+5m / T+15m / T+30m / T+60m（可选 T+180m）方向收益、最大浮盈/回撤、是否命中 SL/TP
  - 模板评估推荐用 T+30m 与 T+60m；短线冲击用 T+5m/T+15m 辅助

### 16.3 特征与 Regime（分钟级）
- Regime 识别：滚动 ATR 分位、布林带宽度、区间突破/假突破比、当期振幅（例如最近 60–120 分钟）
- 候选模板：受限组合以防维度爆炸（示例）
  - `tf_agree_min >= 2 或 3`（5m/15m/1h/4h MACD 同向的最少周期数）
  - `vol_z >= 1.5`（成交量 Z 分数）
  - `oi_chg_15m >= +3%`
  - `funding_abs <= 0.005`
  - `price_vs_ema20`（按周期分层）

### 16.4 统计评估门槛（日内推荐）
- 最小样本：模板 ≥ 80，全局 ≥ 250（不足不出覆盖）
- 显著性：Wilson 下界 `w_lower >= baseline + 5%`；`RR_mean >= 2.0`；Sharpe 提升 ≥ 0.1
- 稳健性：前/后半窗一致；FDR（BH）≤ 10%；时间权重强调最近 6–12 小时

### 16.5 覆盖应用与 TTL（日内）
- 覆盖头（微刷新产物）：TTL 6–12 分钟，仅当“关键模板命中”才注入
- 覆盖文件（主刷新产物）：TTL 2–6 小时；阈值每次最多 ±1（累计 ±2）、冷却 ±1 分钟（区间 6–12）
- 硬护栏不变：BTC 门槛、清单、防假突破、SL/TP、清算距离、冷却下限，均不可通过覆盖改变

### 16.6 运行时集成（如何应用覆盖）
- 方式 A（推荐，最少改动）：在每次 LLM 调用的 prompt 顶部注入“运行时覆盖头”，基线 prompt 文件不改；覆盖过期则不再注入
- 方式 B（更稳）：在 LLM 外层按“合成参数（默认+覆盖）”做硬校验与验收；即使模型越界，也强制按合成参数执行/拒绝
- 二者可并用：A 让模型理解当次偏好并写入 reasoning；B 保证数值边界 100% 生效
  注：覆盖头与覆盖文件中的时间戳一律使用 UTC。

运行时覆盖头示例（当关键三项命中时注入，本头信息 TTL 9 分钟）：
```
运行时策略覆盖（有效期至 2025-01-03T02:00Z）
- regime: trending
- confidence_threshold_base: 79（默认 80，本次 -1，区间 78–85）
- checklist_min_hits: 默认 4/7；关键三项（趋势共振+放量+BTC 状态）同时满足可放宽为 3/7
- trial_entry: 开启；当信心在 78..80 且关键三项齐时，risk_budget_pct=0.5%
- 注：BTC 门槛/防假突破/SLTP/清算距离/冷却下限等硬规则不变
```

### 16.7 Tuner 的角色与实现选项（可选）
- 规则脚本（推荐起步）：不依赖 LLM，仅按显著性与样本阈值生成小幅微调与 TTL，输出覆盖文件 + 变更说明，人工审批后生效
- 混合：LLM 仅用于生成“报告/解释文案”；数值由规则产生并受护栏限制
- 全 LLM（不推荐早期）：必须有严格 schema 校验、幅度上限、回放验证与失败回滚；否则容易漂移

### 16.8 日内示例（关键三项 → 试探单）
- 11:30 微刷新命中关键三项；当前清单命中仅 3/7，客观信心 = 79
- 主刷新（10:00 生成，TTL 4 小时）已有建议：阈值 -1；关键三项齐时允许 3/7；开启试探单 0.5%
- 执行端在 11:30–11:39 的覆盖头有效期内：
  - 若再次命中并满足风控，允许开极小“试探单”；所有硬护栏（SL/TP、BTC 门槛、防假突破、清算距离、冷却下限）照常执行
  - 覆盖头过期后自动回退为默认
